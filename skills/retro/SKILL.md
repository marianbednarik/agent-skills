---
name: retro
description: Learn from a completed work session and recommend improvements to agent guidance, project context, and tooling. Use when asked for a retrospective or feedback on how the collaboration worked.
---

Help future sessions benefit from what this session revealed.

Use the current conversation unless another session is specified. Ground
observations in available messages, actions, and results. Make important
gaps in the available history clear.

Look for consequential friction or useful discoveries: repeated user
corrections, stale instructions or commands, missing context, unnecessary
work, skill misfires, review gaps, and difficulties finding information
or using tools. Recognize approaches worth preserving when the session
provides a concrete lesson.

Distinguish a guidance problem from an execution mistake. Before proposing
new instructions, check whether existing guidance already addressed the
situation and whether it was available, clear, and followed.

Recommend the smallest useful improvement. This may mean correcting or
removing guidance, improving its discoverability, fixing a tool, adding
a worthwhile automated check, or recording agreed project understanding.
An isolated mistake does not automatically justify a permanent rule.

Keep each improvement with its appropriate owner:

- Durable project intent and decisions belong in existing project context.
  Use project-context when establishing or refreshing that understanding.
- Project-specific workflow and setup belong in their authoritative
  documentation or tooling.
- Reusable behavior belongs in a skill or personal guidance only when
  the evidence supports applying it beyond this project.

Preserve one source of truth. Distinguish already-agreed intent from a
new preference or policy the session merely suggests.

Present worthwhile findings in conversation, ordered by expected benefit.
For each, explain what happened, its consequence, the proposed improvement,
and where it belongs. Include uncertainty that affects the recommendation.

Apply corrections within the user's authorized update scope. Otherwise,
present concrete proposals. Report what changed and what remains proposed.

Use existing verification evidence; investigate further only when needed
to support a finding. Surface any discovered unfinished implementation
work explicitly and handle it according to the authorized task scope.

A retro may conclude that no persistent changes are warranted. Finish
when the useful lessons and actionable improvements are clear.
